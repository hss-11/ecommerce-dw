# 指标口径字典

> 版本：v1.1｜创建日期：2026-09-18｜最近修订：2026-10-12（W4 落地后精确化）
> 本文档定义 ecommerce-dw 全部指标的统一口径。任何报表、分析、文档中的
> 指标含义以本文档为准；口径变更必须先改本文档并留 git 记录。

## 1. 全局约定

- 币种：BRL（巴西雷亚尔），不做汇率转换，所有金额指标同币种可比
- 时间基准：数据覆盖 2016-09-04 至 2018-10-17；涉及"当前/最近"的计算
  （如 RFM 的 R）锚点写死为 2018-10-18（数据集最大日期的后一天），禁止使用真实当天日期
- 状态分类：有效 = delivered；无效 = canceled / unavailable；
  进行中 = shipped / invoiced / processing / created / approved（不计入成交类指标）
- 兜底值：'unknown'（类目翻译缺失 / 地理信息缺失）、'uncategorized'
  （商品本身无类目，610 个）。二者含义不同，均不得混入真实类目参与 Top 排名
- 标记字段速查：is_valid_order / is_on_time / is_payment_missing /
  is_not_defined_payment / is_review_id_reused（定义见 modeling.md）
  ⚠️ is_valid_order = 1 表示 delivered + 进行中（非无效订单），与"有效 = delivered"不同口径——成交类指标必须用 order_status = 'delivered' 过滤，只筛 is_valid_order = 1 会多算进行中订单

## 2. 交易规模指标

### 2.1 GMV（商品成交总额）

| 要素 | 口径 |
| --- | --- |
| 定义 | 已成交订单的商品金额与运费之和，衡量平台成交规模 |
| 计算公式 | SUM(item_price + freight_value)，WHERE order_status = 'delivered' |
| 来源表 | dwd_fact_order_item |
| 是否含运费 | 含（freight_value 是买家实付的组成部分） |
| 排除状态 | canceled / unavailable / 全部进行中状态（进行中会让历史数值隔天重算时变化，GMV 必须可回溯） |
| 币种 | BRL |
| 时间口径 | 按下单日（order_purchase_timestamp）归属 |
| 参考值 | ≈15,419,773.75 BRL（W4 全周期实测） |
| 已知局限 | ①不含退款扣减（数据集无退款字段）；②与支付流水存在分期利息差异，两者不相等属正常 |

### 2.2 支付流水

| 要素 | 口径 |
| --- | --- |
| 定义 | 全部支付记录的金额之和，反映资金侧实际发生的支付行为总量 |
| 计算公式 | SUM(payment_value)，不过滤任何订单状态 |
| 来源表 | dwd_fact_payment |
| 是否含分期利息 | 含（payment_value 是消费者实付总额，含金融机构收取的分期利息） |
| 是否含无效订单支付 | 含（全部 canceled / unavailable 订单的支付合计 269,735.11 BRL。其中 775 个无商品明细订单对应 830 笔 / 162,591.95 BRL，属退款场景资金流出（W1 补查 10）；注意该 775 单含 8 个进行中状态订单，纯无效状态子集为 767 单 / 822 笔 / 161,676.89 BRL） |
| 币种 | BRL |
| 时间口径 | 按批准日（order_approved_at 代理）归属——payments 表无独立时间字段 |
| 参考值 | ≈16,008,872.12 BRL（W4 全周期实测） |
| 已知局限 | ①不等于 GMV（含分期利息且含无效订单支付）；②时间口径为代理值，支付发生时刻无法精确 |

### 2.3 平台实收

| 要素 | 口径 |
| --- | --- |
| 定义 | 剔除无效订单后平台真正落袋的支付金额，回答“平台真正收到多少钱” |
| 计算公式 | SUM(payment_value)，WHERE order_status NOT IN ('canceled', 'unavailable') |
| 来源表 | dwd_fact_payment |
| 是否含分期利息 | 含（无法从 payment_value 中剥离，属口径固有边界） |
| 是否含无效订单支付 | 不含 |
| 币种 | BRL |
| 时间口径 | 按批准日（order_approved_at 代理）归属 |
| 参考值 | ≈15,739,137.01 BRL（W4 全周期实测） |
| 已知局限 | ①含分期利息，与 GMV 存在系统性差异，二者不相等属正常；②含进行中订单的支付（在途资金），与成交口径存在时间差 |

### 2.4 订单量

| 要素 | 口径 |
| --- | --- |
| 定义 | 已成交订单的数量，衡量平台交易单量规模 |
| 计算公式 | COUNT(*)，WHERE order_status = 'delivered' |
| 来源表 | dwd_fact_delivery |
| 排除状态 | canceled / unavailable / 全部进行中状态（理由同 2.1 GMV：数值必须可回溯） |
| 时间口径 | 按下单日（order_purchase_timestamp）归属 |
| 参考值 | 96,478 单（W1 探查基准，W4 实测一致） |
| 已知局限 | 776 个无商品明细订单中约 1% 为非无效状态，若其中存在 delivered 订单，会计入订单量但不贡献 GMV（影响可忽略） |

> 选表要点：订单量问的是“多少单”，dwd_fact_delivery 一行 = 一个订单，粒度天然匹配，
> COUNT(*) 即可；若错用 dwd_fact_order_item（一行 = 一个商品项）就得 COUNT(DISTINCT order_id)。
> 选对与你问题粒度匹配的事实表，DISTINCT 就消失了。

### 2.5 客单价

| 要素 | 口径 |
| --- | --- |
| 定义 | 平均每笔已成交订单的成交金额，衡量单笔订单的消费水平 |
| 计算公式 | GMV ÷ 订单量，即 2.1 与 2.4 的结果先各自算出再相除；禁止在明细行上直接求均价 |
| 来源表 | 派生指标（由 2.1 GMV 与 2.4 订单量派生） |
| 是否可加 | 不可加（比率类指标）；不能对每日客单价求和，任意聚合粒度须"先加总分子分母、再相除"重算 |
| 币种 | BRL |
| 时间口径 | 按下单日归属，分子分母均继承 2.1 与 2.4 口径（仅 delivered） |
| 参考值 | ≈159.83 BRL（= 15,419,773.75 ÷ 96,478，W4 全周期实测） |
| 已知局限 | ①单均 ≠ 人均（一个用户可有多单，人均消费须另设指标）；②继承 GMV 局限：不含退款扣减、仅 delivered 订单计入 |

## 3. 用户行为指标

### 3.1 复购率

| 要素 | 口径 |
| --- | --- |
| 定义 | 统计窗口内下单 ≥2 次的购买用户占比，衡量用户的再次购买意愿 |
| 计算公式 | 窗口内下单次数 ≥2 的用户数 ÷ 窗口内有下单的用户数；分子分母一律按 customer_unique_id 去重 |
| 来源表 | dwd_fact_delivery（一行 = 一个订单），经 customer_key 关联 dim_customer 取 customer_unique_id，按人去重计数 |
| 时间窗口 | 必须先声明窗口再出数，本项目两口径：①全周期（2016-09-04 至 2018-10-17，参考值 ≈3.1%，即 2,997 ÷ 96,096 的精确值）；②90 天滚动（按下单日向前推 90 天）。注：W1 探查笔记的 ≈3.5% 系近似算法（3,345 个超额 customer_id ÷ 96,096，三单以上用户被重复计数），W4 落地时按本口径修正 |
| 统计行为 | 下单行为（全部订单状态计入，含无效与进行中——复购衡量"再次下单"意愿，非成交） |
| 时间口径 | 按下单日（order_purchase_timestamp）归属 |
| 已知局限 | ①若误用 customer_id 去重，结果恒为 0（customer_id 一单一号，W1 发现②，🔴 面试高频）；②临近数据末端的用户 90 天滚动窗口不完整，后期数值被低估 |

### 3.2 N 日留存

| 要素 | 口径 |
| --- | --- |
| 定义 | 某日首次下单的用户中，第 N 天再次下单的用户占比，衡量首购人群的留得住程度 |
| 计算公式 | 首购日为 D 且在第 D+N 天再次下单的用户数 ÷ 首购日为 D 的用户数；N 取 7 / 30 / 90 三档 |
| 来源表 | dwd_fact_delivery（首购日 = 该 customer_unique_id 的最早下单日 MIN） |
| 时间窗口 | 观察窗口为首购日后 N 天；"第 N 天"指日历天 D+N（当日口径），写报表时必须声明，否则数值无法对账 |
| 指标性质 | 复购留存（行为 = 再次下单），不是 App 活跃留存——数据集中没有启动 / 浏览事件 |
| 统计行为 | 下单行为，同 3.1（全部订单状态计入） |
| 时间口径 | 按首购下单日归属人群队列（cohort） |
| 已知局限 | ①首购日距数据末端（2018-10-17）不足 N 天的队列观察期不完整，窗口内不可能留存，必须剔除出分母或单独标注，否则留存率被系统性低估；②全量跨度约 25.4 个月，N=90 只对早期首购队列充分适用 |

### 3.3 RFM 分层

| 要素 | 口径 |
| --- | --- |
| 定义 | 用户价值三分量模型：R 最近一次购买间隔 / F 购买频次 / M 消费金额；本条目只定三分量口径，打分与分层阈值规则 W5 再定 |
| R（Recency） | 锚点日期 − 用户最后一次下单日，单位天，值越小越近；锚点 = 2018-10-18（见第 1 节时间基准），禁止使用真实当天日期 |
| F（Frequency） | 观察期内用户下单的次数，按 customer_unique_id 分组统计订单数；一单多件仍算 1 次；计入全部订单状态（与 M 的仅 delivered 不同） |
| M（Monetary） | 观察期内用户成交总额，口径继承 2.1 GMV（SUM(item_price + freight_value)，仅 delivered），单位 BRL |
| 来源表 | dwd_fact_delivery（R / F）+ dwd_fact_order_item（M） |
| 时间窗口 | 观察期 = 全周期 2016-09-04 至 2018-10-17；R 的锚点 = 2018-10-18（最大日期的后一天） |
| 时间口径 | F / M 按下单日汇总归属；R 本身是相对锚点的量，不做日级归属 |
| 已知局限 | ①数据集是静态快照，R 不随真实时间流动——新数据接入后必须重新锚定；②M 用 GMV 口径，与 2.2 支付流水 / 2.3 平台实收存在分期利息与无效订单支付差异，三者不可混用（口径三兄弟） |

## 4. 履约与体验指标

### 4.1 转化漏斗

| 要素 | 口径 |
| --- | --- |
| 定义 | 下单 → 批准 → 发货 → 送达各环节到达订单占全部订单的比例，衡量履约链路通过率 |
| 计算公式 | 各环节订单数 ÷ 全部订单数；到达以对应阶段时间戳非空判定：批准 = order_approved_at，发货 = order_delivered_carrier_date（快递揽收），送达 = order_delivered_customer_date |
| 来源表 | dwd_fact_delivery（一行 = 一个订单全生命周期，累积快照自带各阶段时间戳） |
| 统计范围 | 分母 = 全部订单，不过滤任何状态（含无效与进行中订单，也含 776 个无商品明细订单）——漏斗回答"走到哪一步"，不是"成交没有" |
| 时间口径 | 按下单日（order_purchase_timestamp）归属 |
| 已知局限 | ①orders 表是状态快照：只能看每个订单当前停在哪个阶段，无法还原真实流转轨迹（如批准后又取消）；②时间戳非空只是"到达"的近似，不是事件日志，各阶段占比是相对全部订单的累计通过率，不是环节间转移率 |

### 4.2 准时交付率

| 要素 | 口径 |
| --- | --- |
| 定义 | 完成配送的订单中按承诺时限送达的占比，衡量履约体验 |
| 计算公式 | SUM(is_on_time) ÷ COUNT(*)；is_on_time = 实际送达时间戳 ≤ 承诺送达时间戳（时间戳级比较；承诺字段时间分量恒为 00:00:00，若退化为日期级比较会漏算 1,292 单延迟，定义见 modeling.md） |
| 来源表 | dwd_fact_delivery |
| 统计范围 | 仅 delivered 且实际送达、承诺送达两个时间戳均非空的订单；未送达订单（进行中 / 无效）不进分母 |
| 参考值 | ≈91.9%（延迟 7,827 单，约 8.1%；W4 实测 91.89% = 88,649 ÷ 96,476） |
| 时间口径 | 按下单日归属（与履约类一致） |
| 已知局限 | ①8 单 delivered 缺实际送达时间不入算（W4 对 W1 发现⑦的精确化——W1 笔记中 138 系行数歧义，真实缺时间戳为 8 单；承诺送达时间字段无缺失），对账时须声明分母口径；②承诺送达时间为平台预估口径，本指标是"兑现承诺率"，不等于物流商服务质量评分 |

### 4.3 平均配送时长

| 要素 | 口径 |
| --- | --- |
| 定义 | 已送达订单从下单到实际送达的平均耗时，衡量履约总速度 |
| 计算公式 | AVG(实际送达时间 − 下单时间)，单位：天 |
| 来源表 | dwd_fact_delivery |
| 是否可加 | 时长可加但相加无业务意义，实务只用 AVG（与 modeling.md 时长类度量定性一致） |
| 过滤 | 仅 delivered 且实际送达时间非空；8 单 delivered 缺送达时间不入算（W1 发现⑦的 W4 精确化）；未送达订单本无送达时间，天然排除 |
| 时间口径 | 按下单日归属（与履约类一致） |
| 参考值 | ≈12.56 天（W4 全周期实测，仅 delivered 且送达时间非空） |
| 已知局限 | ①均值受长尾拖拽（少数超时无送达订单拉高数值），报表建议同时给出中位数（P50）；②口径为"下单 → 送达"全链路时长，含卖家处理与物流在途；如需纯物流时长应另立"发货 → 送达"指标独立声明，不得与本指标混用 |

### 4.4 评分分布与留评率

| 要素 | 口径 |
| --- | --- |
| 定义 | 两个子指标：评分分布 = 1～5 分各自占比；留评率 = 带评论文字的评价占比 |
| 计算公式 | 分布 = 各分值 COUNT(*) ÷ 总行数；留评率 = SUM(has_comment) ÷ COUNT(*) |
| 来源表 | dwd_fact_review（组合主键 (order_id, review_id)，全量 99,224 行不去重） |
| 统计要求 | 评分必须给分布，只报均值是错误做法：分布呈 U 型极化（5 分 57.78% ＋ 1 分 11.51%，合计 69.3%），均值 ≈4.09 恰好掩盖该特征 |
| 参考值 | 留评率 ≈41.3%（W4 实测 41.29%；58.7% 的评价无文字——用户只打分不写字属正常现象，非数据质量问题） |
| 时间口径 | 按评价创建日（review_creation_date）归属 |
| 已知局限 | ①分母为行数（评价 × 订单关联数），非独立 review_id 数：789 个 review_id 被复用到多订单、卷入 1,603 行、膨胀 814 行，使两个口径相差约 0.8%，以 is_review_id_reused 标记持续监控；②评价挂在订单而非商品，经订单明细归因到商品时一单多品会重复计数（见 modeling.md 总线矩阵设计说明）；③涉及评论文字的文本分析受 58.7% 缺失率限制，样本非随机，结论须声明边界 |
